## A. microSD（P0，阻塞整个存储层）

产品要求「每天的心情 + 每条语音笔记都存到 SD 卡，可回看最近三个月」，SD 是这个 App 的唯一持久化介质。
公开文档只说 SD 是 SPI 模式、CS = GPIO 8、与墨水屏共用 SPI2，**Registry 里没有任何 App 真正用过 SD 卡**，
所以我们完全没有可参考的实测代码。

| # | 问题 | 我们的假设 | 假设错了的后果 |
|---|---|---|---|
| A1 | SD 卡座有没有 **卡检测（CD）/ 写保护（WP）** 脚？如果有，是哪个 GPIO？ | 没有，靠软件容错 | 插拔卡时我们会写出脏数据 |
| A2 | SD 的供电是否受某个 **EN / 电源开关脚** 控制？还是常供电？ | 常供电 | 不拉高 EN → 卡永远不响应，我们会误判成"卡坏了" |
| A3 | SD 走的是 **3.3V 直连还是电平转换**？官方固件用的 SPI 时钟是多少？ | 3.3V 直连，10 MHz（与面板同速） | 时钟过高 → 偶发 CRC 错，最难查的一类 bug |
| A4 | 官方固件挂载 SD 用的是 `esp_vfs_fat_sdspi_mount` 吗？文件系统 **FAT32 还是 exFAT**？支持多大容量？ | FAT32，≤32 GB | exFAT 需要额外配置；用户插 128 GB 卡会挂载失败 |
| A5 | **面板和 SD 共用 SPI2，官方是怎么串行化的？** 互斥锁？还是从设计上就不并发（刷新期间不碰 SD）？ | 我们自己加一把 SPI2 总线锁，刷新和 busy 等待期间绝不发起 SD 传输 | 并发 → 花屏或总线挂死，且现象随机 |
| A6 | 面板正在 BUSY（GPIO 18 拉高，可能持续数秒）时，SD 的 CS 保持无效是否足够？还是必须把 SD 从总线上断开？ | CS 无效即可 | 需要额外隔离电路的话，我们的软件方案不成立 |

> **如果 A1–A6 有官方示例代码或原理图片段，直接发给我们比逐条回答更快。**

## C. 按键与电源时序（P0，阻塞"按一下就息屏/关机"这个核心体验）

| # | 问题 | 我们的假设 | 假设错了的后果 |
|---|---|---|---|
| C1 | 三个按键（GPIO 4 / 5 / 6）是 **低有效** 吗？上拉是芯片内部上拉，还是板上已有外部上拉电阻？ | 低有效 + 内部上拉 | 极性反了 → 所有按键逻辑失效 |
| C2 | **AI/电源键（GPIO 4）长按是否有硬件级行为？** 比如 PMIC 长按 N 秒硬切断电源轨，绕过固件？ | 纯软件 GPIO，无硬件关机逻辑 | 我们把"长按 600 ms"绑成手势的话，会和硬件关机打架，表现为"莫名关机" |
| C3 | `POWER_HOLD`(45) + `POWER_LOCK`(46) 的**准确时序**：脉冲宽度要求多少？必须先 hold 再 lock，还是可以同帧？释放（hold=0 + lock 脉冲）之后 3.3V 轨多久掉电？ | hold 置电平 → lock 低→高→低各 10 µs | 时序不对 → 松手即黑屏，或该关机时关不掉 |
| C4 | **最关键**：释放电源锁存、整轨掉电之后，ESP32-S3 的 **RTC 域是否还有电**？RTC 慢速内存和 EXT1 唤醒源是否保留？ | **不保留**（视为冷启动） | 见下方说明 |
| C5 | 唤醒是"按电源键重新给整轨上电"（= 冷启动，跑 bootloader）还是"EXT1 从 deep sleep 唤醒"（= 不跑 bootloader）？官方固件走哪条？ | 两条都存在，官方 demo 用 deep sleep | 决定我们要不要维护两套恢复路径 |
| C6 | PCF8563 RTC 有**备份电池或超级电容**吗？整轨掉电后时间还在吗？ | 没有，掉电即丢时间 | 每次开机都必须联网 SNTP 校时，离线开机就显示错误日期 |

### 关于 C4，为什么这条最关键

墨水屏断电后画面**物理保留**，所以"关机后仍显示最后一次心情"这个体验不依赖 RTC 内存。
但 App 状态（当前页面、今天记了没记）原本打算存 RTC 保持内存 —— 如果整轨真的掉电，那份内存内容是不可信的。

**我们的应对**：不赌 C4，App 状态改存 **NVS/SD**，开机读回来。
需要 Lily 确认的只是"这样是否多此一举"—— 如果 RTC 域其实有电，我们可以省掉一次 SD 读写。

## F. GPIO 7 的归属（P1，一句话就能回答）

官方硬件文档把 GPIO 7 标为 **LSM6DS3TR-C IMU 的中断**，
但 Registry 的 App 源码里把它当作 **BQ27220 电量计的中断**（`PIN_BFG_INT`）。两个器件都挂在 I2C1 上。

**问：GPIO 7 到底接的是谁？** 我们只需要读电量，不需要 IMU；如果两个中断真的共用一个脚，
我们就不注册中断、改成定时轮询电量计，避免误判。
